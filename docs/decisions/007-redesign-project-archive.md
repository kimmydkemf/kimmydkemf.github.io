# 사이트를 "프로젝트 아카이브" 구조로 재설계한다

날짜: 2026-10-01

## 배경

사용자가 모바일 깨짐과 긴 페이지, 기존과 다른 태그 표시를 지적한 뒤 "개선이 아닌 재설계"를 요청했다. 처음 보는 사람의 눈으로 다시 보니 첫 화면 전체가 이름과 좌우명뿐이라 무엇을 만든 사람인지 보이지 않았고, 다크(네온)와 라이트(크림 + 섹션 번호 + 그라데이션 블롭)가 서로 다른 디자인이었으며, 프로젝트는 전부 같은 모양의 행이라 중요한 것이 구분되지 않았다. 떠다니는 "Claude 탐구 중" 배지는 내용을 가렸다.

## 결정

1. 페이지 순서를 표지 → 프로젝트 → 소개 → 연락으로 바꾼다. 프로젝트가 증거이고 소개는 보조다.
2. 표지는 이력서 표지처럼 왼쪽 이름·한 줄 소개·버튼(프로젝트 보기 · 이메일 · GitHub), 오른쪽 사실 요약으로 구성한다. 사실 요약의 숫자(프로젝트 수, 진행 중, 완료, 아카이브, 기록 시작, 마지막 동기화)는 sync 가 `STATS` 마커 구간에 쓰고 JS 가 같은 JSON 으로 다시 그린다.
3. 진행 중 · 완료는 2열 카드 그리드(열면 전체 폭), 미사용 · 아카이브는 연도 타임라인 한 줄 카드로 보여준다. 아카이브는 기본으로 펼쳐 둔다 (한 줄 카드라 짧다).
4. 강조색은 하나(잉크 블루). 상태 색은 의미색으로 분리하고 태그는 무채색 모노 글꼴로 통일한다. 두 테마는 토큰만 다르고 구조는 같다. 라이트 전용 장식(섹션 번호, 블롭, 스트라이프)과 떠다니는 배지는 없앤다. 배지의 문장은 소개로 옮겼다.
5. 글꼴은 IBM Plex Sans KR + IBM Plex Mono (Google Fonts, 시스템 글꼴 폴백).
6. 영문 섹션 이름(ABOUT/SKILLS/PROJECTS/CONTACT)을 한국어(프로젝트/소개/연락)로 바꾸고, 기술(Skills)은 소개 안의 한 블록으로 합친다.
7. 데이터 파이프라인(sync, JSON, 마이그레이션 파서, 테스트)은 그대로 둔다. 카드의 클래스 이름(`proj-title`, `proj-period`, `chip`, `dl-section` …)을 유지해 파서와 테스트가 계속 동작한다. Python 과 JS 렌더러는 parity 테스트로 같은 출력을 보장한다.
8. SPEC §29 "디자인 정체성을 크게 훼손하지 않는다" 보다 사용자의 명시적 재설계 요청을 우선했다.

## 영향

- `index.html`, `assets/css/style.css` 전면 교체. `scripts/render_cards.py`, `assets/js/projects.js` 의 카드 마크업 변경.
- 측정 (Playwright): 데스크톱 페이지 4030 → 3408px, 모바일 3665 → 4851px. 모바일이 길어진 이유는 아카이브 6개를 접지 않고 타임라인으로 보여주고 소개를 늘렸기 때문이다. 가로 넘침 없음, 콘솔 오류 없음.
- 테마 저장 방식이 `data-theme="light"|"dark"` 명시 + 저장값 없으면 시스템 설정을 따르는 방식으로 바뀌었다.

## 되돌릴 조건

- 사용자가 미리보기를 보고 방향을 바꾸면 이 커밋 이전으로 되돌린다. 데이터 레이어는 영향 없다.
